# dsh-chatlog

把 DSH 的每个会话导出成本地纯文本文档，并按「还活着 / 已归档」自动分文件夹。

## 规则

```
/sdcard/dsh/DshChat/<标题>-<会话号8位>.txt              还活着的会话
/sdcard/dsh/DshChat/DeletedChat/<标题>-<会话号8位>.txt  归档的、或会话文件已经不在了的
```

- **活着** = 磁盘上还有它的会话文件，或本轮对话正在往它上面写事件。
- **归档** = `~/.dsh/storages/workspace.json` 的 `global.archivedSessionIds` 里有它。
  DSH 界面上的「删除会话」其实就是归档：只往这个集合里加一个 id，会话文件原地不动。
- 会话文件被删掉（或整个会话目录搬家）之后，对应的文档也会自动进 `DeletedChat`。
- **会话文件已经没了的文档只搬不写**。源没了、内容重建不出来，那份 .txt 就是唯一存本，
  插件不会拿任何「期望内容」去覆盖它。

## 它是怎么写的：对账，不是追加

会话文件是唯一真源，文档是派生物。每次变动不「往下写」，而是：

1. 重新算一遍这个会话**现在应该长什么样**；
2. 和磁盘上那份实际内容比；
3. **只改不一致的地方** —— 从最后一块往前对，对到哪块不一样就从哪块重写；
   正常对话只多出一两条消息时，实际写入只有几百字节，而不是整份重写。

这样做的效果：会话被回退、消息被改、标题被改名、归档状态翻转、
甚至文档被外部半截写坏，都会在下一轮自动收敛到正确状态 —— 不需要为每种情况写专门分支。

### 会话日志是只追加的，所以要按表面操作折叠

DSH 的会话文件只追加：删消息、改消息、回退重做，都是再写一条带

```json
"surfaceOp": { "op": "replace", "startSeq": 35, "endSeq": 36 }
```

的事件，把旧的那一段从「表面」上摘掉。这是 DSH 会话格式自身的字段（不是某个插件的私有约定），
`@deepseek-ai/dsh-session` 自己读会话时也是这么折叠的。插件只认结构、不认任何 id 前缀，
所以任何写入方（核心、扩展、未来的功能）的改动都能被正确对待。

## 触发时机

| 时机 | 动作 |
| --- | --- |
| 收到任意会话事件 | 1 秒后对账一次（`liveMs` 可调，`0` = 关掉） |
| 每轮结束（`turn/end`） | 立刻对账，并顺手搬一次文件（归档/消失不会发事件，只能靠这个兜） |
| 每 60 秒 | 全量对账一次（`syncMs` 可调） |
| 插件启动 | 全量对账一次 |

会话文件没变（`mtime` + `size` + 归档集合都没动）时直接跳过，连解压都不做。

## 文件归属

- 每份文档开头都写着自己是哪个会话（`会话  session-...` 那一行），
  插件只靠这一行认领文件 —— **不是自己写的 .txt 一概不读不写不删不改名**。
- 目标文件名总带会话号；如果撞上别人（包括你手写的）同名文件，会自动加长会话号避让，
  不会覆盖。
- 一个会话只保留一份文档：标题变了就换新名，旧的那份删掉。

## 配置

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关掉后不再导出，也不会再搬文件 |
| `dir` | `/sdcard/dsh/DshChat` | 输出根目录 |
| `archiveSubdir` | `DeletedChat` | 归档子目录名 |
| `tz` | `Asia/Shanghai` | 文档里的时间用哪个时区 |
| `showTools` | `true` | 是否记下工具调用与结果 |
| `showReasoning` | `false` | 是否记下模型的思考内容 |
| `maxResultLines` | `6` | 单条工具结果最多保留几行 |
| `clean` | `true` | 去掉 Markdown 标记，输出干净的纯文本 |
| `liveMs` | `1000` | 消息变动后多久落盘；`0` = 只在每轮结束时落盘 |
| `syncMs` | `60000` | 后台全量对账间隔；`0` = 只在启动和每轮结束时对账 |
| `skipSubagents` | `true` | 跳过子代理会话 |

## 文档长什么样

```
DSH 对话记录
标题  去完成我学习通上的作业
会话  session-12e98f31-c76b-4f97-8267-2e865d0595b8
目录  /root
开始  2026/10/30 12:04:25
时区  Asia/Shanghai

—— 2026/10/30 12:05:15 · 你 ——
去完成我学习通上的作业

—— 2026/10/30 12:05:18 · 助手 ——
先看一下手机状态。

—— 2026/10/30 12:05:18 · 工具 ——
→ phone_status {}
← phone_status
  无障碍服务: 已开启
  当前前台: com.dshmobile.probe
```

文档里**没有「导出时间」这一行**：带时间戳的话每次对账都「不一致」，就永远得整份重写。
文件本身的修改时间就是最后一次更新。

## 出问题先看这里

`DshChat/.chatlog-state.json`：

| 字段 | 含义 |
| --- | --- |
| `written` | 真正动了盘的次数（改了哪怕一个字节） |
| `appended` | 其中「只追加/截断尾部」的次数 |
| `rewritten` | 其中「整份重写」的次数 |
| `unchanged` | 对账后完全一致、一个字都没写的次数 |
| `moved` | 搬文件次数 |
| `errors` / `lastError` | 出错计数与最后一条错误 |

写盘细节：整份重写走「临时文件 + rename」，不会出现写到一半的文档；
原地增量改（截断 + 追加）不是原子的，但下一轮对账会发现块对不上并自动整份重写兜底。
崩溃残留的临时文件（`.chatlog-<pid>.<tag>.tmp`）超过 6 小时会在下次启动时清掉。
